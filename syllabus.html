Module 1 Linux Foundations Sessions 1–2
✎
Module quiz activity — Short written quiz covering Linux architecture, FHS, the boot process, CLI text-processing tools, and pipe composition. Administered at the start of Session 3.
01
Linux Architecture
Kernel, shell, filesystem hierarchy, boot process
▾
Theory
  • Unix history → Linux and FOSS philosophy
  • Kernel space, user space, shell layer model
  • Popular distros and when to choose each
  • FHS: /, /etc, /bin, /var, /proc, /sys
  • Boot sequence: BIOS → GRUB → kernel → systemd
  • systemd: targets, unit files, dependency graph
Labs
  • Install Ubuntu 22.04 Server on VirtualBox
  • Explore FHS — document each top-level directory
  • Read hardware info via /proc and /sys without external tools
  • Run systemd-analyze blame; identify the 3 slowest services
02
CLI & Text Processing
Shell, pipes, grep, awk, sed — the core toolkit
▾
Theory
  • Navigation: ls, cd, find, locate
  • File operations: cp, mv, rm, ln (hard vs soft links)
  • Redirection: >, >>, 2>, 2>&1, /dev/null
  • Pipes and xargs — composing commands
  • Text tools: grep, sed, awk, sort, uniq, cut, wc, tr
  • vim basics, alias, .bashrc configuration
Labs
  • Count top 10 IPs from access.log using awk + sort + uniq
  • Bulk-replace strings in a config file using sed
  • Create hard and soft links; compare inodes with ls -i
  • Configure .bashrc with useful aliases and environment variables
Module 2 System Administration Sessions 3–4
✎
Module quiz activity — Scenario-based questions on user/group management, permission models (SUID/SGID/sticky bit, ACLs), sudo configuration, LVM operations, and cron syntax. Administered at the start of Session 5.
03
Users, Permissions & Processes
Who can do what — access control and process management
▾
Theory
  • useradd, usermod, userdel, groupadd
  • /etc/passwd, /etc/shadow, /etc/group structure
  • chmod (octal + symbolic), chown, chgrp, umask
  • Special bits: SUID, SGID, sticky bit
  • Extended ACLs: getfacl, setfacl
  • sudo, /etc/sudoers, principle of least privilege
  • Process management: ps, top, kill, nice, renice, nohup, tmux
Labs
  • Create dev and ops groups; assign users appropriately
  • Set ACLs on a project directory: dev read-write, ops read-only
  • Configure restricted sudo for a deploy user
  • Use tmux: create a session, detach, reattach after SSH reconnect
04
Software, Storage & Scheduled Tasks
apt, LVM, cron, systemd timers
▾
Theory
  • apt / dpkg: install, remove, version pinning, PPAs
  • Building from source: configure, make, make install
  • Partitioning: fdisk, lsblk, mkfs, mount, /etc/fstab
  • LVM: PV, VG, LV — create and expand online
  • cron: 5-field syntax, crontab -e, /etc/cron.d
  • systemd timer: .timer unit files as a cron alternative
Labs
  • Create an LVM volume, format, mount and persist via /etc/fstab
  • Expand the LV by 5 GB online without unmounting
  • Install nginx, pin the version, verify with apt-mark hold
  • Create a cron job logging a timestamp every minute; verify after 5 min
Module 3 Networking & Security Sessions 5–6
✎
Module quiz activity — Practical in-class quiz covering all content from Modules 1–3. Students complete tasks on a live VM: configure networking, harden SSH, set firewall rules, and interpret security logs. Held during Session 6 lab time.
05
Network Configuration & SSH
Connectivity, file transfer and secure remote access
▾
Theory
  • ip addr, ip route, nmcli — static IP and DHCP
  • /etc/hosts, /etc/resolv.conf, dig, nslookup
  • Diagnostics: ss, ping, traceroute, curl, wget
  • sshd_config: port, PermitRootLogin, AllowUsers
  • SSH key pairs, authorized_keys, ~/.ssh/config
  • SSH ProxyJump through a bastion host
  • File transfer: scp, rsync
Labs
  • Set a static IP on a VM using nmcli
  • Generate SSH key pair; configure passwordless login between two VMs
  • Configure ~/.ssh/config with aliases for multiple servers
  • Sync a web directory to a backup VM with rsync; schedule via cron
06
Firewall & System Hardening
UFW, fail2ban, auditd — module quiz this session
▾
Theory
  • UFW: allow, deny, limit, logging rules
  • iptables: INPUT / OUTPUT / FORWARD chains, NAT basics
  • fail2ban: jail.conf, filters, actions
  • SSH hardening: disable root login, change port, AllowUsers
  • PAM: password policy, login limits
  • auditd: track access to sensitive files
  • journalctl and /var/log/auth.log — reading security logs
  • Lynis: automated hardening audit and scoring
Labs
  • Configure UFW: open only ports 22, 80, 443
  • Install fail2ban, simulate SSH brute-force, confirm IP is banned
  • Install auditd, watch /etc/passwd and /etc/shadow for access events
  • Run Lynis, record the score, remediate 3 HIGH warnings
Module 4 Application Deployment Sessions 7–9
✎
Module quiz activity — Written quiz on web server configuration (Nginx/Apache), database access control and backup strategies, and systemd service management. Administered at the start of Session 10.
07
Web Servers — Nginx & Apache
Virtual hosts, reverse proxy, SSL/TLS
▾
Theory
  • Nginx vs Apache: processing models and trade-offs
  • Nginx: server block, root, index, location directives
  • Apache: VirtualHost, .htaccess, mod_rewrite
  • PHP-FPM + Nginx: unix socket vs TCP socket
  • Nginx reverse proxy: proxy_pass, header forwarding
  • SSL/TLS with certbot (Let's Encrypt)
  • Nginx: rate limiting, gzip compression, log formats
Labs
  • Create 2 Nginx virtual hosts serving two websites on one server
  • Install PHP-FPM and connect to Nginx via unix socket
  • Configure Nginx as a reverse proxy for an app on a high port
  • Generate and apply a self-signed SSL certificate for the lab
08
Database Servers — MySQL & PostgreSQL
Installation, access control, backup and restore
▾
Theory
  • Install MySQL / PostgreSQL, run mysql_secure_installation
  • Create DB users, GRANT / REVOKE privileges
  • mysqldump, pg_dump — full and per-database backup
  • Restore and verify data integrity
  • bind-address — restrict DB to localhost only
  • Slow query log — identify expensive queries
Labs
  • Install MySQL, create an application user and database
  • Back up all databases with mysqldump + gzip
  • Restore a database from backup into a new schema; verify data
  • Set up automated backup via cron; configure email alert on failure
09
Deploying a Real Web Application
Flask/Node.js + systemd + Nginx + SSL
▾
Theory
  • Running Python (Flask/FastAPI) or Node.js apps on Linux
  • Writing a systemd .service unit for an application
  • Restart policies: on-failure, always
  • Environment variables via EnvironmentFile
  • Logging to journald via stdout/stderr
  • Nginx reverse proxy + SSL for the application
  • Safe deployment workflow: test → reload → rollback
Labs
  • Write a systemd service for Flask/Node.js with automatic restart
  • Configure an EnvironmentFile for secrets (DB password, API key)
  • Place the app behind Nginx reverse proxy with SSL
  • Simulate a crash; confirm systemd restarts and journals the event

Student seminar topics

10 topics · 30–45 min per presentation · goal: real-world awareness + career readiness

# Topic Area Why it matters
01 Ansible — configuration management and automation Automation Most in-demand sysadmin skill; appears in nearly every DevOps job description
02 Prometheus + Grafana — metrics monitoring and dashboards Monitoring Industry-standard observability stack; used across startups and enterprises alike
03 HAProxy — load balancing and high availability Networking Bread-and-butter for web infrastructure; handles millions of requests in production
04 Redis — in-memory caching and data structures Application Behind nearly every high-traffic web app for caching and session storage
05 NFS — network file sharing between Linux servers Storage Core network storage protocol; heavily used in on-prem and hybrid environments
06 Git server — self-hosted repository over SSH DevOps Connects version control to Linux admin; immediately employable skill
07 Zabbix — enterprise host and network monitoring Monitoring Widely deployed in large organizations and government infrastructure
08 SysStat — historical performance analysis (sar, iostat, mpstat) Performance Essential for diagnosing CPU, disk, and I/O bottlenecks; used daily by sysadmins
09 Docker CE — containerisation and image-based deployment DevOps Most widely adopted container runtime; foundational for understanding modern deployment pipelines
10 ELK Stack — centralised log management (Elasticsearch, Logstash, Kibana) Monitoring Industry-standard log aggregation and search platform; heavily used in operations and security teams
Prerequisites: Students should be comfortable with basic programming (loops, conditionals, functions) and have completed at least one networking or OS fundamentals course. All lab work uses VirtualBox VMs running Ubuntu 22.04 Server. No cloud provider accounts or Docker knowledge is required.

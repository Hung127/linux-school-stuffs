Unix at Bell Labs (1969)

Ken Thompson and Dennis Ritchie built Unix at AT&T Bell Labs as an OS for the PDP-7. They invented the C programming language specifically to rewrite it — and that decision shaped every OS that followed. Unix introduced pipes, a hierarchical filesystem, and the "everything is a file" philosophy.

↳ Real impact: the pipe operator | you use every day was invented here.

User Space
Applications run in user space — they cannot directly touch hardware. If your app crashes, the kernel kills the process. The rest of the system keeps running. This isolation is why a crashing browser doesn't take down your whole machine.
$ ps aux | grep nginx
nginx 1234 0.0 nginx: master process
nginx 1235 0.0 nginx: worker process
Every file read, network call, and fork goes through syscalls ↓

/etc
System-wide configuration files. Every installed service drops its config here. This is the first place you look when something misbehaves — the source of truth for how the system is configured.
/etc/nginx/nginx.conf      ← nginx web server config
/etc/ssh/sshd_config       ← SSH daemon settings
/etc/hosts                  ← local DNS overrides
/etc/fstab                  ← filesystem mount table
/etc/passwd                 ← user account database
/etc/shadow                 ← hashed passwords (root only)
⚠ Never delete files in /etc without a backup. A corrupt /etc/fstab can prevent the system from booting.

GRUB Bootloader
GRUB (Grand Unified Bootloader) is the first piece of software with a human-readable interface. It reads /boot/grub/grub.cfg, presents a menu (hold Shift to see it), loads the chosen kernel image into RAM, and hands off control. This is where you select which kernel version to boot — critical for rollbacks after a bad kernel update.
# Edit GRUB config (never edit grub.cfg directly)
$ sudo nano /etc/default/grub
$ sudo update-grub

# View available kernels
$ ls /boot/vmlinuz-*
INCIDENT REPORT

Back to 3 AM.
Here's how it unfolds.

The disk is full. But it's /var — the directory for variable data. Logs, application data, package cache. Something filled it up while you slept.

Everything you need — systemd, journalctl, df, du — is knowledge you now have. Let's walk through the real resolution.

Time to resolution: 14 minutes
Root cause: unbounded log rotation
Impact: $180K in failed transactions

Incident timeline
03:01:44
payment-api crashes. systemd marks it failed. Customers see 502 errors.
systemctl status payment-api
03:07:21
On-call engineer SSHs in. Reads journalctl logs. Spots ENOSPC: no space left on device.
journalctl -u payment-api -n 50 --no-pager
03:08:05
Checks disk usage. /var is 100%. Hunts for the culprit with du — finds 18 GB of unrotated nginx access logs in /var/log/nginx/.
du -sh /var/* | sort -rh | head -10
03:11:33
Compresses old logs. Frees 16 GB. Restarts payment-api. Service comes back up. Transactions resume.
gzip /var/log/nginx/access.log.* && systemctl start payment-api
03:15:44
Configures logrotate to cap nginx logs at 100 MB with weekly rotation. Sets up disk-usage alert at 80%. Goes back to sleep.
nano /etc/logrotate.d/nginx # maxsize 100M, rotate 7

.service — Running a daemon
A service unit tells systemd how to start, stop and restart a process. The most important fields: ExecStart (what to run), Restart (when to restart), and WantedBy (which target pulls it in).
# /etc/systemd/system/payment-api.service
[Unit]
Description=Payment Gateway API
After=network.target postgresql.service

[Service]
ExecStart=/opt/payment/app
Restart=on-failure
RestartSec=5s
EnvironmentFile=/etc/payment.env

[Install]
WantedBy=multi-user.target

Quick check — click your answer

Let's see what stuck

Q1 — You run cat /proc/meminfo on a freshly mounted USB drive and get "No such file or directory". Why?
A) /proc requires root access
B) /proc is a virtual FS generated in kernel memory, not stored on any disk
C) The USB drive is formatted as FAT32
D) meminfo is binary and can't be read with cat
✓ Correct. /proc and /sys only exist while the system is running — they're generated live by the kernel. No disk, no file.
✗ Not quite. /proc is a virtual filesystem that only exists in memory — it cannot be present on a physical storage device.
Q2 — Your server's disk is 100% full (from the 3 AM case). What is the first command you run to find the largest directory?
A) ls -la /
B) find / -size +1G
C) du -sh /* | sort -rh | head -10
D) df -h /
✓ Correct. du -sh summarises each directory's size, sort -rh sorts human-readable sizes descending, head -10 shows the top culprits.
✗ df shows partition usage but not which directory is the culprit. du -sh /* | sort -rh | head -10 finds the biggest directory trees.
Q3 — What is the correct boot sequence order?
A) Kernel → GRUB → BIOS → systemd → initramfs
B) BIOS → GRUB → Kernel → initramfs → systemd
C) GRUB → BIOS → initramfs → Kernel → systemd
D) BIOS → Kernel → GRUB → systemd → initramfs
✓ Correct. BIOS does hardware check → GRUB loads the kernel → kernel initialises hardware → initramfs mounts temporary root → systemd starts services.
✗ The correct order is BIOS → GRUB → Kernel → initramfs → systemd. GRUB must come before the kernel — it's the bootloader that loads it.

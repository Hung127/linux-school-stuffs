cat — the source of data
The pipeline starts here. cat reads the entire file and writes it to stdout. The pipe | connects stdout of one command to stdin of the next — no temporary files, no disk I/O between steps. The kernel handles this entirely in memory using a ring buffer. Each command in the pipeline runs simultaneously as separate processes — that's why pipelines are fast even on huge files.
>
Redirect stdout
Write output to file. Overwrites if exists.
cmd > output.txt
>>
Append stdout
Add output to end of file. Safe for logs.
cmd >> output.txt
2>
Redirect stderr
Write errors only. Stdout goes to terminal.
cmd 2> errors.txt
2>&1
Merge streams
Send both stdout and stderr to same place.
cmd > all.txt 2>&1

awk — the columnar surgeon

A mini programming language for structured text

awk reads files line by line, splits each line into fields ($1, $2 ...), and runs your program on each one. Nginx logs are perfectly structured — every field has a position.

BEGIN { }→Run once before any input
/pattern/ { }→Run for each matching line
{ }→Run for every line
END { }→Run once after all input
# Nginx log field positions:
$1=IP  $7=URL  $9=status  $10=bytes
192.168.1.45 - - [date] "POST /api" 500 523
Click an example to see it run
awk '{print $1}' access.log
Extract column 1 — the IP address from every line
awk '$9 == 500 {print $1, $7}' access.log
Only 500 errors — print IP and URL
awk '{sum += $10} END {print sum/1024/1024 "MB"}' access.log
Total bandwidth served — sum the bytes column
awk '$9==200 {c++} END {print c " OK requests"}' access.log
Count successful requests without grep | wc -l
awk '{ip[$1]++} END {for(i in ip) print ip[i], i}' access.log

Hard links · Soft links · Inodes

Understanding what a "file" really is in Linux

Inode #42 (the actual data)
type: regular file
permissions: rw-r--r--
owner: deploy:www-data
size: 18,432 bytes
links: 2 ← reference count
blocks: [4821, 4822, 4823]
↑ inodes don't have names ↑
↑ ↑
app.conf
hard link → inode 42
app.conf.bak
hard link → inode 42
current → /etc/nginx/sites-enabled/app
symlink (stores a path)
old-link → /etc/nginx/sites-enabled/deleted
broken symlink — target gone
Hard link — another name for the same inode
A hard link is just a directory entry pointing to an inode. The file data exists once; both names are equal. Deleting one name decrements the link count — the data is only freed when count reaches 0. You cannot hard-link across filesystems or hard-link directories.
$ ln app.conf app.conf.bak
$ ls -li app.conf app.conf.bak
42 -rw-r--r-- 2 deploy app.conf
42 -rw-r--r-- 2 deploy app.conf.bak
# Same inode (42), link count = 2
$ rm app.conf # link count drops to 1
$ cat app.conf.bak # data still here!
Real scenario: nginx uses symlinks for virtual hosts. /etc/nginx/sites-enabled/myapp is a symlink to /etc/nginx/sites-available/myapp. To disable a site: rm /etc/nginx/sites-enabled/myapp — the config file stays safe in sites-available. Re-enable with ln -s.

find & xargs — searching and acting at scale

find locates. xargs scales. Together they're unstoppable.

❌ The slow way — shell loop
# Runs one process per file
for f in $(find /logs -name "*.log"); do
  gzip "$f"
done
# 10,000 files = 10,000 gzip processes
# Time: ~4 minutes
Each iteration spawns a new process. Huge overhead for thousands of files. Also breaks on filenames with spaces.
✓ The fast way — xargs with parallelism
# Batches args, runs in parallel
find /logs -name "*.log" -print0 \
  | xargs -0 -P4 gzip
# -0 handles spaces in filenames
# -P4 runs 4 gzip processes at once
# Time: ~35 seconds
xargs reads stdin, batches arguments, and passes them to a command. -P4 runs 4 parallel processes — uses all CPU cores.

3 real sysadmin scenarios

Q1 — You want to find all lines in /var/log/auth.log containing "Failed password" and count unique source IPs. Which pipeline is correct?
A) grep "Failed password" auth.log | cut -d' ' -f1 | sort | uniq
B) grep "Failed password" auth.log | awk '{print $11}' | sort | uniq -c | sort -rn
C) cat auth.log | grep -c "Failed" | awk '{print $1}'
D) sed '/Failed password/p' auth.log | cut -f11
✓ Correct. In auth.log, field $11 is the source IP. uniq -c counts occurrences, sort -rn shows the worst offenders first. This is exactly how you detect SSH brute-force attacks.
✗ Field $11 contains the source IP in auth.log's "Failed password" lines. You need awk '{print $11}' to extract it, then sort | uniq -c | sort -rn to count and rank.
Q2 — A developer hardcoded db_host=localhost in /etc/app/config.conf. You need to change it to db_host=10.5.0.2 without opening an editor. Which command works correctly?
A) sed 's/localhost/10.5.0.2/' /etc/app/config.conf
B) grep -r 's/localhost/10.5.0.2/g' /etc/app/config.conf
C) sed -i 's/localhost/10.5.0.2/' /etc/app/config.conf
D) awk '{gsub(/localhost/,"10.5.0.2")}' /etc/app/config.conf
✓ Correct. The -i flag tells sed to edit the file in place. Without -i, sed just prints the result to stdout — the file stays unchanged. Option D would need {print} and output redirection to actually save.
✗ The key is -i (in-place). Without it, sed prints to stdout but doesn't change the file. sed -i 's/localhost/10.5.0.2/' file modifies the actual file on disk.
Q3 — You delete the original file report.txt after creating both a hard link report_hard.txt and a soft link report_soft.txt to it. What happens?
A) Both links break immediately
B) Both links continue to work normally
C) report_hard.txt still works; report_soft.txt is broken
D) report_soft.txt still works; report_hard.txt is deleted too
✓ Correct. The hard link points directly to the inode — data survives until all hard links are removed. The soft link stores the path to report.txt, which no longer exists. This is why nginx uses symlinks for sites-enabled — you can safely remove and re-create them.
✗ Hard links point to the inode (the actual data). Deleting report.txt removes one directory entry but the inode still has a link count of 1 (the hard link). The soft link stores the path "/path/to/report.txt" which no longer resolves — it becomes dangling.

alias rm='rm -i'              # always confirm delete
alias cp='cp -i'              # confirm overwrites
alias mv='mv -i'

# ── Shortcuts ───────────────────────
alias ll='ls -lah'            # detailed list
alias la='ls -A'
alias grep='grep --color=auto'

# ── Sysadmin shortcuts ──────────────
alias ports='ss -tulnp'        # open ports
alias meminfo='free -h'
alias diskinfo='df -h'
alias topcpu='ps aux --sort=-%cpu | head -10'
alias logs='journalctl -f'       # live system logs
💡 After editing .bashrc, run source ~/.bashrc or open a new terminal to apply changes. The file is sourced (executed) every time an interactive shell starts.
